# ADR-002: SQLite 作为默认存储

## 状态: 已采纳
## 日期: 2026-06-11
## 决策者: CarryMem 核心团队

---

## 上下文

CarryMem 是一个**个人级 AI 记忆管理系统**，核心需求是持久化存储用户的记忆条目（文本内容、元数据、向量嵌入）。需要选择一个合适的存储后端作为默认选项。

关键约束：
- **零配置启动**：用户安装后应能立即使用，无需额外安装数据库服务。
- **单用户场景**：典型使用场景是单个开发者在本地机器上使用。
- **便携性**：数据文件应易于备份、迁移和版本控制。
- **查询能力**：需要支持全文搜索、过滤、排序、分页等操作。
- **并发安全**：CLI 多命令并行执行时需保证数据一致性。

## 候选方案

| 方案 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| **A: SQLite** ✅ | 内嵌式关系数据库，Python 标准库内置驱动 | 零依赖；单文件便携；ACID 事务；支持 JSON 和 FTS5 全文搜索；并发 WAL 模式 | 写入性能不如 PostgreSQL；不适合多机分布式场景 |
| **B: PostgreSQL** | 客户端-服务器关系数据库 | 强一致性和高并发能力；丰富的扩展生态（pgvector） | 需要额外安装和运维；对个人工具过重 |
| **C: JSON 文件** | 直接读写 JSON 文件 | 最简单；人类可读 | 无索引；大数据量下性能差；无事务保证；并发不安全 |
| **D: MongoDB / DuckDB** | NoSQL / 分析型数据库 | MongoDB schema灵活；DuckDB分析能力强 | 均需额外依赖；MongoDB 需要服务进程 |

## 决策

**采用方案 A：SQLite 作为默认存储后端。**

具体实现：

```python
# src/carrymem/adapters/sqlite/ 目录下实现完整适配器
# - connection.py   : 连接池与 WAL 模式管理
# - schema.py       : 表结构定义（memories, rules, backups 等）
# - crud.py         : 增删改查基础操作
# - query_builder.py: 动态 SQL 构建
# - recall_engine.py : 向量召回与全文搜索
# - security.py     : 加密字段读写
# - versioning.py   : 记忆版本链管理
# - stats.py        : 统计信息聚合查询
```

关键设计决策：
- **WAL 日志模式**：启用 Write-Ahead Logging，允许并发读和单一写。
- **FTS5 全文搜索**：为记忆内容建立虚拟全文搜索表，支持中文分词。
- **JSON 列存储**：元数据使用 JSON 列存储，保留 Schema 灵活性。
- **Adapter 抽象层**：通过 `StorageAdapter` 协议隔离具体实现，未来可切换到其他后端。

## 后果

### 正面
- **零依赖开箱即用**：用户 `pip install carrymem` 后即可运行，无需安装数据库。
- **单文件备份**：整个数据库就是一个 `.db` 文件，复制即备份。
- **事务安全**：所有写操作包裹在事务中，崩溃不会导致数据损坏。
- **FTS5 中文搜索**：利用 SQLite FTS5 的 tokenizer 扩展支持中文全文检索。
- **测试友好**：测试时可使用 `:memory:` 临时数据库，速度极快且无副作用。

### 负面
- **写入瓶颈**：SQLite 的写锁是库级别的，高并发写入场景可能成为瓶颈。但对个人工具来说足够。
- **无内置向量索引**：SQLite 原生不支持向量相似度搜索，需要在应用层实现（当前使用内存中的 numpy 计算）。
- **文件大小增长**：随着记忆积累，`.db` 文件会持续增大，需配合清理策略。
- **跨平台路径问题**：Windows/Linux/macOS 的文件锁定行为略有差异。

### 缓解措施
- 使用连接池 (`connection.py`) 复用连接，减少锁竞争。
- 定期运行 `carrymem clean --expired` 清理过期记忆。
- 提供 `VACUUM` 维护命令压缩数据库文件。
- 通过 Adapter 抽象层保留切换到 PostgreSQL/DuckDB 的可能性。
