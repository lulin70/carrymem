# ADR-003: 双后端加密策略

## 状态: 已采纳
## 日期: 2026-06-11
## 决策者: CarryMem 核心团队

---

## 上下文

CarryMem 存储用户的个人偏好、决策记录、事实声明等敏感信息。这些数据**默认应加密存储**，防止数据库文件被直接读取时泄露隐私。

加密方案面临的关键挑战：

1. **依赖最小化**：CarryMem 应尽量减少第三方依赖，但加密是安全敏感领域。
2. **降级兼容**：如果用户环境没有安装 `cryptography` 库，系统仍应提供基本保护。
3. **密钥管理**：密钥如何安全生成、存储和轮换。
4. **性能开销**：加密/解密不应显著影响用户体验。

## 候选方案

| 方案 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| **A: 仅 cryptography (Fernet)** | 强制依赖 `cryptography` 库，使用 Fernet (AES-128-CBC + HMAC) | 行业标准；经过充分审计 | 增加依赖；纯 Python 环境可能缺失该库 |
| **B: 仅标准库 (HMAC-CTR)** | 仅用 Python 标准库实现 AES-CTR 流密码 | 零额外依赖 | 自研加密方案安全性未经审计；不建议用于生产 |
| **C: 双后端自动降级** ✅ | 优先使用 Fernet，不可用时回退到 HMAC-CTR | 兼顾安全性与可用性；优雅降级 | 两套实现需分别维护；HMAC-CTR 分支安全性较弱 |

## 决策

**采用方案 C：Fernet + HMAC-CTR 双后端加密策略，带自动降级。**

架构分层：

```
                    ┌─────────────────────┐
                    │   EncryptionBackend  │  ← 统一接口 (encrypt/decrypt)
                    └──────────┬──────────┘
                               │
              ┌────────────────┼────────────────┐
              ▼                                 ▼
    ┌──────────────────┐              ┌──────────────────┐
    │  FernetBackend   │              │  HMACCTRBackend  │
    │ (cryptography)   │              │ (stdlib only)    │
    │ AES-128-CBC+HMAC │              │ HMAC-SHA256+CTR  │
    │ 安全级别: strong │              │ 安全级别: weak   │
    └──────────────────┘              └──────────────────┘
              ▲                                 ▲
              │          自动选择               │
    ┌─────────┴─────────────────────────────────┴─────────┐
    │              BackendSelector                        │
    │  1. 尝试导入 cryptography → Fernet                  │
    │  2. ImportError → 回退到 HMAC-CTR + 发出警告        │
    │  3. 用户显式指定 security_level → 尊重选择          │
    └─────────────────────────────────────────────────────┘
```

三档安全级别：

| 级别 | 后端 | 说明 | 适用场景 |
|------|------|------|---------|
| `"strong"` | Fernet | AES-128-CBC + HMAC-SHA256 | **生产推荐**；`cryptography` 可用时自动选用 |
| `"weak"` | HMAC-CTR | PBKDF2-HMAC-SHA256 密钥派生 + CTR 流密码 | 无 `cryptography` 库时的降级方案 |
| `"none"` | NoEncryption | 明文透传 | 仅限测试环境或显式禁用 |

密钥管理：
- 密钥文件位置：`~/.carrymem/.key`（权限 600）
- 完整性校验：`~/.carrymem/.key.digest`（HMAC-SHA256 校验和）
- 密钥派生：PBKDF2-HMAC-SHA256，迭代次数 600,000+
- 加密字段：仅加密 `content` 和 `original_message`；元数据（type/tier/confidence）明文存储以支持查询

## 后果

### 正面
- **最大可用性**：即使在没有 `cryptography` 的最小环境中也能提供基本加密保护。
- **透明升级**：用户安装 `cryptography` 后自动获得强加密，无需任何配置变更。
- **灵活控制**：高级用户可通过配置指定安全级别，满足不同安全需求。
- **审计友好**：NoEncryption 后端方便安全审计和渗透测试。

### 负面
- **双倍维护成本**：两套加密实现都需要维护和测试。
- **HMAC-CTR 安全性存疑**：自研的 CTR 流密码实现未经过专业安全审计，不应被视为生产级安全。
- **密钥丢失风险**：密钥文件损坏意味着所有已加密数据永久不可恢复（by design）。
- **迁移复杂性**：从 HMAC-CTR 迁移到 Fernet 时需要重新加密所有现有数据。

### 缓解措施
- 启动时检测并发出明确的安全级别警告（SecurityWarning）。
- 文档中强烈推荐安装 `cryptography` 库。
- 提供 `carrymem doctor --security` 命令检查当前加密状态。
- HMAC-CTR 后端代码添加大量注释说明其局限性。
