## 1. 项目概况

### 1.1 项目定位

CarryMem定位为"AI身份层"，这是一个独特且有价值的定位：
- ✅ **差异化明显**: 不同于传统对话记忆系统
- ✅ **用户痛点清晰**: 解决AI工具间身份不连续问题
- ✅ **技术路线创新**: 零依赖、规则引擎、技能包格式

### 1.2 核心特性

1. **自动分类** (7种记忆类型)
2. **语义召回** (跨语言支持)
3. **身份画像** (whoami功能)
4. **规则引擎** (独有特性)
5. **技能包格式** (可移植规则集)
6. **MCP集成** (23个工具)
7. **CLI工具** (40+命令)

### 1.3 技术栈

- **语言**: Python 3.9+
- **存储**: SQLite + FTS5
- **加密**: AES-128 (Fernet)
- **测试**: pytest (2056个测试)
- **覆盖率**: 77.12%

## 2. 架构分析

### 2.1 目录结构

```
carrymem/
├── src/carrymem/  # 核心引擎
│   ├── adapters/                      # 存储适配器
│   ├── coordinators/                  # 分类协调器
│   ├── integration/                   # 外部集成
│   ├── layers/                        # 分类层
│   ├── rules/                         # 规则引擎
│   ├── security/                      # 安全模块
│   ├── semantic/                      # 语义处理
│   └── utils/                         # 工具函数
├── tests/                             # 测试套件
├── docs/                              # 文档
├── benchmarks/                        # 基准测试
└── examples/                          # 示例代码
```

### 2.2 架构优点

✅ **清晰的分层设计**
- 适配器层、协调层、规则层分离良好
- 符合单一职责原则

✅ **可扩展性强**
- 适配器模式支持多种存储后端
- 规则引擎支持自定义规则

✅ **零依赖设计**
- 仅依赖SQLite，部署简单
- 无需向量数据库

### 2.3 架构问题

⚠️ **模块耦合度偏高**
- `carrymem.py` 文件过大（可能超过1000行）
- 部分功能可以进一步模块化

⚠️ **命名不一致**
- 包名 `carrymem` vs 导入名 `carrymem`
- 计划统一，但当前造成困惑

⚠️ **缺少接口定义**
- 部分模块缺少明确的接口契约
- 建议使用Protocol或ABC
