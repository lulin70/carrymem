## 1. 背景与目标

### 1.1 需求来源

用户指示：将原定 v0.8.0（多模式检索）和 v0.9.0+（异步管道、向量检索、Memify 动态精炼）的功能，压缩到 v0.7.1 和 v0.7.2 两个小版本中实现。

### 1.2 版本号策略说明

| 规则 | 说明 |
|------|------|
| 项目 SemVer 规则 | 功能新增应 MINOR 递增（v0.8.0, v0.9.0） |
| 用户要求 | v0.7.1, v0.7.2（PATCH 递增） |
| **决策** | **遵循用户要求 v0.7.1/v0.7.2**。在 0.x.x 阶段，SemVer 允许 PATCH 引入新功能（API 本身不稳定）。所有新功能向后兼容，不破坏现有 API。 |

### 1.3 目标

将 4 个原定长期方案功能压缩到 2 个小版本：

| 版本 | 功能 | 原定版本 | 优先级 |
|------|------|----------|--------|
| v0.7.1 | 多模式检索完善 + 向量语义检索 API | v0.8.0 | P2 |
| v0.7.2 | Memify 动态精炼 + 异步管道增强 | v0.9.0+ | P1-P3 |

```python
def recall_by_time(
    self,
    start: datetime,
    end: Optional[datetime] = None,
    filters: Optional[Dict[str, Any]] = None,
    limit: int = 50,
) -> List[Dict[str, Any]]:
    """Retrieve memories within a time range (v0.7.1).

    Args:
        start: Start datetime (inclusive). Timezone-aware recommended.
        end: End datetime (exclusive). Defaults to now.
        filters: Optional metadata filters (same as recall()).

    Returns:
        List of memory dicts ordered by created_at descending.
    """
```

```sql
SELECT * FROM memories
WHERE created_at >= ? AND created_at < ?
  AND namespace = ?
  AND deleted_at IS NULL
ORDER BY created_at DESC
LIMIT ?
```

### 4.2 Memify 动态精炼设计

#### 4.2.1 derive_facts — 派生事实

```python
def derive_facts(
    self,
    namespace: str = "default",
    min_co_occurrence: int = 3,
    max_derived: int = 10,
) -> List[Dict[str, Any]]:
    """Derive new facts from frequently co-occurring entities (v0.7.2).

    Analyzes memory_entities to find entity pairs that co-occur in ≥3
    memories. For each such pair, creates a derived "relationship" memory.

    Args:
        namespace: Namespace scope.
        min_co_occurrence: Minimum co-occurrence count (default 3).
        max_derived: Maximum derived facts per run (default 10).

    Returns:
        List of derived memory dicts with:
        - type: "relationship"
        - content: "Entity A and Entity B frequently co-occur (N times)"
        - metadata: {"derived": True, "co_occurrence": N}
    """
```

**SQL 实现**:
```sql
-- Find co-occurring entity pairs
SELECT e1.entity_text AS e1, e2.entity_text AS e2, COUNT(*) AS co
FROM memory_entities e1
JOIN memory_entities e2 ON e1.memory_key = e2.memory_key
  AND e1.id < e2.id
  AND e1.namespace = e2.namespace
WHERE e1.namespace = ?
GROUP BY e1.entity_text, e2.entity_text
HAVING co >= ?
ORDER BY co DESC
LIMIT ?
```

#### 4.2.3 auto_decay — 自动衰减

```python
def auto_decay(
    self,
    namespace: str = "default",
    stale_days: int = 90,
    min_importance: float = 0.3,
    batch_size: int = 100,
) -> int:
    """Auto-decay stale, low-importance memories (v0.7.2).

    Marks memories as "outdated" tier if:
    - last_accessed_at is older than stale_days
    - importance_score < min_importance
    - access_count == 0 (never recalled)

    Outdated memories are not deleted — they're excluded from default
    recall() results unless explicitly requested via filters={"tier": "outdated"}.

    Args:
        namespace: Namespace scope.
        stale_days: Days without access to be considered stale (default 90).
        min_importance: Importance threshold (default 0.3).
        batch_size: Batch size for processing (default 100).

    Returns:
        Number of memories decayed to outdated tier.
    """
```

**SQL 实现**:
```sql
UPDATE memories
SET metadata = json_set(metadata, '$.tier', 'outdated'),
    importance_score = importance_score * 0.5
WHERE namespace = ?
  AND deleted_at IS NULL
  AND last_accessed_at < ?
  AND importance_score < ?
  AND access_count = 0
  AND (json_extract(metadata, '$.tier') IS NULL
       OR json_extract(metadata, '$.tier') != 'outdated')
LIMIT ?
```

#### 4.2.4 集成到 consolidate_memories

```python
# consolidation.py
def consolidate_memories(self, namespace: str = "default") -> Dict[str, Any]:
    """Consolidate memories: derive facts, reinforce edges, auto-decay."""
    result = {"derived_facts": [], "edges_reinforced": 0, "decayed": 0}

    # Phase 1: Derive facts from co-occurring entities
    result["derived_facts"] = self._memify.derive_facts(namespace=namespace)

    # Phase 2: Reinforce graph edges
    result["edges_reinforced"] = self._memify.reinforce_edges(namespace=namespace)

    # Phase 3: Auto-decay stale memories
    result["decayed"] = self._memify.auto_decay(namespace=namespace)

    return result
```

### 4.3 异步管道增强设计

#### 4.3.1 AsyncSQLiteAdapter — aiosqlite 原生异步

**设计原则**:
- aiosqlite 添加到 `[async]` extra（不进入核心依赖）
- AsyncSQLiteAdapter 复用 SQLiteAdapter 的 SQL 逻辑，但用 aiosqlite 连接
- 双模式共存：同步 SQLiteAdapter（零依赖核心）+ AsyncSQLiteAdapter（[async] extra）

```python
# adapters/async_sqlite.py
class AsyncSQLiteAdapter:
    """Async SQLite adapter using aiosqlite (v0.7.2).

    Requires `pip install carrymem[async]`.
    Same SQL as SQLiteAdapter but with native async I/O.
    """

    def __init__(self, db_path: Optional[str] = None, namespace: str = "default", ...):
        self._db_path = db_path or _default_db_path()
        self._namespace = namespace
        # ... same config as SQLiteAdapter ...

    async def store_entry(self, entry: MemoryEntry) -> StoredMemory: ...
    async def recall(self, query: str, ...) -> List[StoredMemory]: ...
    async def forget_memory(self, memory_key: str) -> bool: ...
    # ... all methods async ...
```

#### 4.3.2 AsyncCarryMem 升级

```python
# async_carrymem.py (升级)
class AsyncCarryMem:
    """Async CarryMem with native async adapter support (v0.7.2).

    Mode 1 (default): Wraps sync CarryMem with run_in_executor (zero deps).
    Mode 2 (native): Uses AsyncSQLiteAdapter for true async I/O (requires [async]).
    """

    def __init__(self, ..., native_async: bool = False):
        if native_async:
            from .adapters.async_sqlite import AsyncSQLiteAdapter
            self._async_adapter = AsyncSQLiteAdapter(...)
        else:
            self._sync = CarryMem(...)
```

## 9. 关键结论

1. **v0.7.1 是低风险快速交付** — 4 个新 API 纯新增，复用已有 RRF 融合和向量基础设施，不修改现有逻辑。

2. **v0.7.2 需要谨慎设计 Memify** — 自动衰减有误降级风险，采用三重条件（stale + low importance + zero access）保守策略。

3. **异步管道保持双模式共存** — AsyncSQLiteAdapter 作为 [async] extra，核心零依赖不变。AsyncCarryMem 默认 executor 包装，可选 native_async=True。

4. **产品初心不可妥协** — 零依赖核心、零 LLM 规则引擎、SQLite 原生、API 稳定。所有新功能通过新方法或可选 extra 暴露。

5. **测试是质量守门员** — 98 个新测试覆盖 6 维度（Happy/Boundary/Error/Performance/Configuration/Integration），回归测试 0 failure。
