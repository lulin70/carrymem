## 上下文工程洞察 (新增 — v0.2.8)

### Lost-in-the-Middle效应对规则注入的影响

LLM注意力遵循U型曲线：**开头和结尾注意力高，中间注意力低**（10-40%召回率下降）。这直接影响规则注入的可靠性。

**当前问题** (v0.2.1-v0.2.7):
```
## 个人规则 (来自CarryMem)
规则A (relevance=0.92, override=true)   ← 开头: 高注意力
规则B (relevance=0.88, override=false)  ← 中间: 注意力坍塌
规则C (relevance=0.85, override=true)   ← 中间: 最重要的规则被忽略！
规则D (relevance=0.80, avoid)           ← 结尾: 次要注意力
```

**v0.2.8解决方案**: 锚定布局模式
```
## 个人规则 (来自CarryMem)

### 绝对禁止 (不可违反)
- [forbid] 绝不在未验证的情况下引用竞品数据     ← 头部锚点

### 推荐行为
- [always] 汉堡仓库需电话确认库存
- [avoid] 跨境调拨优先使用国内仓库

### 强制执行 (不可跳过)
- [always] 所有外部报价必须包含有效期           ← 尾部锚点
```

### 上下文预算监控

当规则注入超过上下文窗口70%时，自动压缩：
- 优先级：保留override=true规则，将avoid规则压缩为摘要
- 超阈值：每条规则一行摘要，不附带来源信息

### DDD语言视图

CarryMem概念映射到DDD概念，实现与企业架构师的对话：

| CarryMem | DDD | 关系 |
|----------|-----|------|
| trigger | 限界上下文(Bounded Context) | 范围定义 |
| rule_type (forbid/avoid/always) | 聚合一致性约束 | 不变量≈forbid, 保证≈always |
| override | 不变量(Invariant) | 不可被更高优先级覆盖 |
| source_memories | 事件溯源链(Event Sourcing Chain) | 规则可追溯到原始经验 |
| refine过程 | 统一语言精炼(Ubiquitous Language Refinement) | 具体→一般抽象 |

实现方式：`format_rules_as_prompt()` 中 `style="ddd"` 参数，仅显示层，不改变存储。

## 安全策略 (纵深防御)

### 第1层: 输入验证 (v0.2.1 ✅)
- Prompt注入模式检测 (10+模式)
- SQL注入字符阻断
- 模板注入防护
- HTML/XSS标签剥离
- 长度限制 (trigger: 200, action: 500)

### 第2层: 使用限制 (v0.2.1 ✅)
- 全局规则上限: 最多3个 trigger="*"
- 总规则上限: 最多200条
- 速率限制: 20/小时, 50/天

### 第3层: 自动晋升安全 (v0.2.5 ✅)
- 自动晋升需用户显式操作
- 所有自动生成规则初始为 `override=false`
- 未确认候选7天过期
- 队列大小限制 (50个待处理)

### 第4层: 经验学习安全 (v0.2.6 ✅)
- 重复记忆检测 (跳过已处理的)
- 消毒器验证所有提取的trigger/action
- 所有经验→规则操作有审计追踪

### 第5层: 精炼安全 (v0.2.7 ✅)
- 每会话最多5轮
- 会话过期 (7天)
- 所有精炼规则经过消毒器

### 第6层: 上下文工程安全 (v0.2.8 规划)
- 上下文预算监控防止提示溢出
- 锚定布局确保关键规则不会丢失在中间
- 压缩策略保留override=true规则
