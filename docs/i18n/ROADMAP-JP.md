## コンテキスト工学インサイト (新規 — v0.2.8)

### Lost-in-the-Middle効果がルール注入に与える影響

LLMのアテンションはU字カーブに従う：**先頭と末尾のアテンションが高く、中央が低い**（10-40%のリコール低下）。これはルール注入の信頼性に直接影響する。

**現在の問題** (v0.2.1-v0.2.7):
```
## 個人ルール (CarryMemから)
ルールA (relevance=0.92, override=true)   ← 先頭: 高アテンション
ルールB (relevance=0.88, override=false)  ← 中央: アテンション崩壊
ルールC (relevance=0.85, override=true)   ← 中央: 最重要ルールが無視！
ルールD (relevance=0.80, avoid)           ← 末尾: 二次的アテンション
```

**v0.2.8ソリューション**: アンカーレイアウトモード
```
## 個人ルール (CarryMemから)

### 絶対禁止 (違反不可)
- [forbid] 競合データを未検証で引用しない          ← ヘッドアンカー

### 推奨行動
- [always] ハンブルク倉庫は電話で在庫確認
- [avoid] クロスボーダー転送は国内倉庫を優先

### 必須実行 (スキップ不可)
- [always] すべての外部引用に有効期限を含める       ← テールアンカー
```

### コンテキスト予算モニタリング

ルール注入がコンテキストウィンドウの70%を超えた場合、自動圧縮：
- 優先度：override=trueルールを保持、avoidルールを要約に圧縮
- 閾値超過：ルールごとに1行要約、ソース属性なし

### DDD言語ビュー

CarryMemの概念をDDD概念にマッピング、エンタープライズアーキテクトとの対話を実現：

| CarryMem | DDD | 関係 |
|----------|-----|------|
| trigger | 境界付けられたコンテキスト(Bounded Context) | スコープ定義 |
| rule_type (forbid/avoid/always) | 集約整合性制約 | 不変条件≈forbid, 保証≈always |
| override | 不変条件(Invariant) | より高い優先度で上書き不可 |
| source_memories | イベントソーシングチェーン(Event Sourcing Chain) | ルールは元の経験まで追跡可能 |
| 精製プロセス | ユビキタス言語の精製(Ubiquitous Language Refinement) | 具体→一般の抽象化 |

実装：`format_rules_as_prompt()` の `style="ddd"` パラメータ、表示のみ、ストレージ変更なし。

## セキュリティ戦略 (多層防御)

### 第1層: 入力検証 (v0.2.1 ✅)
- Promptインジェクションパターン検出 (10+パターン)
- SQLインジェクション文字ブロック
- テンプレートインジェクション防止
- HTML/XSSタグ除去
- 長さ制限 (trigger: 200, action: 500)

### 第2層: 使用量制限 (v0.2.1 ✅)
- グローバルルール上限: 最大3 trigger="*"
- 総ルール上限: 最大200
- レート制限: 20/時間, 50/日

### 第3層: 自動プロモーション安全性 (v0.2.5 ✅)
- 自動プロモーションにはユーザーの明示的操作が必要
- 自動生成ルールは初期 `override=false`
- 未確認候補は7日で期限切れ
- キューサイズ制限 (50保留中)

### 第4層: 経験学習安全性 (v0.2.6 ✅)
- 重複メモリ検出 (処理済みをスキップ)
- サニタイザが抽出されたtrigger/actionを検証
- 全経験→ルール操作に監査証跡

### 第5層: 精製安全性 (v0.2.7 ✅)
- セッションあたり最大5ラウンド
- セッション有効期限 (7日)
- 全精製ルールがサニタイザを通過

### 第6層: コンテキスト工学安全性 (v0.2.8 計画)
- コンテキスト予算モニタリングでプロンプトオーバーフロー防止
- アンカーレイアウトで重要ルールが中央に埋もれない
- 圧縮戦略がoverride=trueルールを保持
