# CarryMem v0.5.2 Specification — Summary Layer + Progressive Disclosure

> **版本**: v0.5.2 (Implementation Spec)
> **创建日期**: 2026-07-02
> **状态**: ✅ 已实现 (v0.5.2 Released 2026-07-02)
> **依据**: [v0.5.0 spec §4.3](v0.5.0_spec.md#43-建议三摘要层--渐进式披露--新功能llm-开关) + 架构探索结果
> **范围**: 为每条记忆生成摘要缓存，recall/prompt 注入时按桶分级披露，降低 token 消耗

---

## 1. 概述

### 1.1 目标

当前 `build_prompt()` 注入每条记忆的完整 `raw_text`，token 消耗高。v0.5.2 为每条记忆生成字段级 `summary` 缓存，按桶分级披露：

| 桶 | depth | 渲染内容 | token 节省 |
|----|-------|----------|-----------|
| Mandatory | 3 (完整) | `[标签] 完整 raw_text` | 0% (保持当前行为) |
| Important | 2 (短) | `[标签] 首句摘要` | ~60% |
| Context | 2 (短) | `[标签] 首句摘要` | ~60% |
| Outdated | 1 (超短) | `[标签] 关键词` | ~90% |

### 1.2 设计原则

- **零 LLM 优先**: 规则式摘要为默认 fallback，LLM 摘要可选（缺省关闭）
- **向后兼容**: `progressive` 参数缺省 `False`，不启用时行为与 v0.5.1 完全一致
- **Simplicity First**: 单文件实现 `layers/summary_layer.py`，不拆 4 文件包
- **复用现有**: LLM 摘要复用 `LLMClient`，不新建 backend 抽象

### 1.3 与现有模块的区分

| 模块 | 作用 | 产出 |
|------|------|------|
| `SessionSummarizer` (已有) | 多条 session 记忆 → 一条新记忆 | 新 `session_summary` 类型记忆 |
| `SemanticAggregator` (已有) | 相似记忆聚类合并 | 新聚合 entry |
| **`SummaryLayer` (v0.5.2 新增)** | **单条记忆 → 字段级摘要缓存** | **`summary`/`summary_level` 字段** |

三者互补不冲突。

## 2. 架构探索结果

### 2.1 当前 prompt 注入流程

```
build_context() [prompt_builder.py:298]
  → _recall_base_memories() → select_memories() → build_prompt()
  → build_prompt() [prompt.py:153]
    → 分桶: Mandatory / Important / Context / Outdated
    → format_memory_entry() [format.py:59] → 注入完整 raw_text
```

**问题**: 所有桶（除 Outdated 截断 80 字符外）都注入完整 `raw_text`，token 浪费严重。

### 2.2 关键集成点

| 改造点 | 文件 | 方法 | 说明 |
|--------|------|------|------|
| 摘要生成 | `layers/summary_layer.py` (新建) | `SummaryLayer.summarize()` | 规则式 + LLM 可选 |
| Schema migration | `adapters/sqlite/schema.py` | `migrate_v052()` | 加 summary + summary_level 列 |
| StoredMemory 扩展 | `adapters/base.py` | `StoredMemory` | 加 summary/summary_level 字段 |
| prompt 渲染 | `prompt.py` | `build_prompt()` | 加 progressive 参数，按桶选 depth |
| format 改造 | `format.py` | `format_memory_entry()` | 接受 depth 参数，depth<3 时用 summary |
| 摘要失效 | `adapters/sqlite/crud.py` | update 路径 | raw_text 更新时清空 summary |
| build_context | `prompt_builder.py` | `build_context()` | 加 progressive 参数透传 |

### 2.3 LLM 开关配置

```
enable_llm_summary 配置优先级:
  1. 环境变量 CARRYMEM_LLM_SUMMARY=1/0  （最高优先级）
  2. TRAE 环境检测: 若 CARRYMEM_ENV=trae 或 TRAE_SESSION_ID 存在 → 自动打开
  3. 缺省: False（保持零 LLM 优势）
```

LLM 关闭时用规则式摘要（取首句 + 类型标签 + 关键词）。
LLM 打开时调用 `LLMClient.chat()` 生成摘要，失败降级到规则式。

## 3. 详细设计

### 3.1 新建模块: `src/carrymem/layers/summary_layer.py`

```python
class SummaryLayer:
    """摘要层 + 渐进式披露。

    规则式摘要为默认 fallback，LLM 摘要可选（复用 LLMClient）。
    摘要缓存到 memories.summary 字段，无 TTL，raw_text 更新时失效。
    """

    def __init__(self, llm_client: Optional[Any] = None):
        self._llm = llm_client
        self._rule_summarizer = RuleBasedSummarizer()

    def summarize(self, memory: Dict[str, Any], level: int = 2,
                  force: bool = False) -> str:
        """生成摘要。level 1=超短, 2=短, 3=完整(返回 raw_text)。

        - 若 memory 已有缓存 summary 且 summary_level >= level 且非 force → 返回缓存
        - 若 LLM 可用且启用 → LLM 摘要，失败降级规则式
        - 否则 → 规则式摘要
        """

    def render_for_bucket(self, memory: Dict[str, Any], bucket: str) -> str:
        """根据桶选择 depth 并渲染。

        Mandatory → depth=3 (完整)
        Important  → depth=2 (短摘要)
        Context    → depth=2 (短摘要)
        Outdated   → depth=1 (超短)
        """


class RuleBasedSummarizer:
    """零 LLM 摘要器。

    策略:
    - user_preference/correction: 取 raw_text 首句 + 类型标签
    - decision: 取 "决定:" 后内容
    - fact_declaration: 取原始声明首句
    - 其他: 取前 80 字符 + "..."
    - level=1: "[标签] 关键词" (取前 3 个实词)
    - level=2: "[标签] 首句"
    - level=3: 返回完整 raw_text
    """

    def summarize(self, memory: Dict[str, Any], level: int = 2) -> str:
        """规则式摘要，零 LLM 依赖。"""
```

### 3.2 Schema Migration `_V052`

```sql
-- _V052_MIGRATION_SQL
ALTER TABLE memories ADD COLUMN summary TEXT;
ALTER TABLE memories ADD COLUMN summary_level INTEGER;
```

- `summary TEXT`: 缓存的摘要文本，NULL 表示未生成
- `summary_level INTEGER`: 摘要深度级别 (1=超短, 2=短)，NULL 表示未生成
- 幂等迁移: 检查列是否存在，已存在则跳过
- `migrate_all()` 末尾调用 `migrate_v052()`

### 3.3 StoredMemory 扩展

`adapters/base.py` 的 `StoredMemory` dataclass 新增:
- `summary: Optional[str] = None`
- `summary_level: Optional[int] = None`

更新 `to_dict()` / `from_dict()` / `types.py` 的 `StoredMemoryDict`。

### 3.4 prompt.py 集成

`build_prompt()` 新增 `progressive: bool = False` 参数:

```python
def build_prompt(memories, knowledge, language="en", progressive=False):
    # progressive=False: 当前行为（完整 raw_text）
    # progressive=True: 按桶选 depth
    #   Mandatory → depth=3 (完整)
    #   Important  → depth=2 (短摘要)
    #   Context    → depth=2 (短摘要)
    #   Outdated   → depth=1 (超短)
```

`format_memory_entry()` 新增 `depth: int = 3` 参数:
- depth=3: 返回完整内容（当前行为）
- depth=2: 返回 `[标签] summary`（若 summary 为空则现场生成规则式摘要）
- depth=1: 返回 `[标签] 关键词`（从 summary 或 raw_text 提取）

### 3.5 摘要缓存与失效

- **缓存**: `summarize()` 生成后，通过 `adapter.update_memory()` 写入 `summary`/`summary_level` 字段
- **失效**: `crud.py` 的 update 路径中，若 `raw_text` 被更新，清空 `summary`/`summary_level`（设为 NULL）
- **无 TTL**: 摘要不自动过期，仅在 raw_text 变更时失效
- **按需生成**: 首次 recall 时生成并缓存，后续命中缓存

### 3.6 build_context 集成

`prompt_builder.py:build_context()` 新增 `progressive: bool = False` 参数，透传到 `build_prompt()`。

`build_system_prompt()` 同步新增 `progressive` 参数。

## 5. 向后兼容

1. `progressive` 缺省 `False` — 不启用时行为与 v0.5.1 完全一致
2. `summary`/`summary_level` 字段默认 NULL — 现有记忆不受影响
3. LLM 摘要器失败时自动降级到规则式 (fail-safe)
4. `format_memory_entry()` 的 `depth` 缺省 `3` — 不传参时行为不变
5. Schema migration 幂等 — 已存在的列不会重复添加

## 7. 风险与缓解

| 风险 | 缓解 |
|------|------|
| 规则式摘要质量不足 | 作为 LLM 关闭时的 fallback，用户可选开启 LLM |
| LLM 摘要延迟 | 缓存到 `summary` 字段；首次 recall 时同步生成（可接受） |
| 摘要丢失关键信息 | Mandatory 桶始终用 depth=3（完整）；摘要仅用于低优先级桶 |
| TRAE 环境误检测 | 多重信号验证 (`CARRYMEM_ENV` + `TRAE_SESSION_ID`) |
| 向后兼容破坏 | `progressive=False` 缺省 + 字段默认 NULL + depth=3 缺省 |

## 8. 安全修正项

| ID | 修正项 | 说明 |
|----|--------|------|
| C20 | 摘要内容经 `InputValidator.sanitize_content()` 处理 | 防止 LLM 输出注入恶意内容到 summary 字段 |
| C21 | LLM prompt 用 `<memory_data>` 标签包裹 raw_text | 防 prompt injection（复用 SessionSummarizer 模式） |
| C22 | summary 字段长度限制 500 字符 | 防止 LLM 输出超长摘要占用过多存储 |
