## 2. 发布流程

```bash

# 2. 本地门禁

# 3. commit + push

# 4. 创建 PR（base: new-main）
gh pr create --title "[V0.10.0] Repeat-correction upgrade (forge 借鉴点 2)" \
             --body "Closes #49. See docs/design/V0.10.0_REPEAT_CORRECTION.md"

gh pr merge 50 --merge --delete-branch

# 6. tag
git tag -a v0.10.0 -m "V0.10.0: repeat-correction upgrade (forge 借鉴点 2)"
```

## 4. 紧急回滚 (Emergency Rollback)

### 方案 1：Feature flag 软回滚（推荐）

```bash
export CORRECTION_UPGRADE_ENABLED=0
# 重启服务（或调用方检测 env 后自动停止升级路径）
```

效果：v0.10.0 新代码仍在，但所有升级路径走默认 disable 分支；旧纠正继续按普通偏好处理。

### 方案 2：单 commit revert

```bash
git revert <v0.10.0-commit-sha>
git push origin new-main
# CI 会自动重新跑全量回归
```

### 方案 3：完整版本回滚

```bash
git checkout v0.9.9
pip install -e .
```

### 方案 4：数据库回滚

v0.10.0 暂不修改 schema。如已发布 v101 schema 需回滚：

```sql
ALTER TABLE memories DROP COLUMN correction_count;
ALTER TABLE memories DROP COLUMN upgrade_chain;
ALTER TABLE memories DROP COLUMN related_corrections;
```

## 5. 已知问题与限制

| 限制 | 影响 | 缓解 |
|------|------|------|
| Jaccard + 实体匹配非向量检索 | 细微语义差异可能漏判 | 用户可手动 engine.add_rule 升级 |
| 仅英文 + 简单中文支持 | 复杂中文语义可能误判 | v0.10.2 加入 LangID + 中文分词 |
| 阈值硬编码默认 2/3 | 不同用户群体可能需要不同阈值 | 环境变量可覆盖 |
| classify_and_remember 集成在 v0.10.1 | 本版本用户需手动调用 | 提供示例代码片段 |

## 6. 决策记录 (Decision Records)

- **DR-V10-001**: 阈值选 2/3 而非 1/2 — 避免单次误纠正升格
- **DR-V10-002**: 语义去重用 Jaccard 而非向量检索 — 零依赖核心原则
- **DR-V10-003**: 安全关键词白名单绕过阈值 — 安全相关纠正不容容忍
- **DR-V10-004**: 升级只升 scope 不改 TTL — 与偏好永不衰减初心对齐
- **DR-V10-005**: 阈值通过环境变量配置 — 支持灰度发布与回滚
