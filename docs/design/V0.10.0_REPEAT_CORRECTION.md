## 1. 设计动机

CarryMem 当前 `classify_and_remember("X")` 把纠正统一存为 `user_preference`，下次是否遵守靠：
1. `recall_memories()` 召回命中率
2. AI 模型自觉性

**痛点**: 用户对 AI 最大的不满来自"同一错误重复犯"。forge 借鉴点 2 —— **重复纠正自动升级为硬约束** —— 直接掐断该循环。

### CarryMem 初心对齐

| 初心 | 设计选择 | 验证 |
|------|---------|------|
| 零依赖 | 纯规则引擎 + 内存阈值计算 | ✅ |
| 便携性 | 阈值状态存 SQLite 主库 | ✅ |
| 偏好永不衰减 | 升级只升 scope，不改 TTL | ✅ |
| 可执行规则 | 升级产物直接是 RuleEngine rule | ✅ |

---

## 2. 架构概览

```
classify_and_remember("corrected message")
         │
         ▼
[分类引擎] → type == "correction"
         │
         ▼
[新] detect_repeat_correction(content)
         │
         ▼
[历史纠正召回]
         │
         ▼
    阈值判定
         │
         ├── 0 次同主题 → 存 user_preference
         ├── 1 次同主题 → 存 + engine.add_rule(scope="personal")
         ├── 2 次同主题 → 存 + engine.add_rule(scope="company", override=True)
         └── 命中安全关键词 → 强制升级
         │
         ▼
ClassificationResult { upgrade_action, upgrade_history_count }
```

## 4. 数据模型

### 4.1 schema 变更（迁移 v101）

```sql
ALTER TABLE memories ADD COLUMN correction_count INTEGER NOT NULL DEFAULT 1;
ALTER TABLE memories ADD COLUMN upgrade_chain TEXT NOT NULL DEFAULT '[]';
ALTER TABLE memories ADD COLUMN related_corrections TEXT NOT NULL DEFAULT '[]';
```

### 4.2 语义去重算法（零依赖）

```python
def _are_corrections_similar(a: str, b: str, threshold: float = 0.7) -> bool:
    """Jaccard + 数字/实体提取。
    示例:
      "端口 5432" vs "用 5432 端口" -> Jaccard 0.8, 数字"5432"匹配 -> 相似
      "端口 5432" vs "端口 8080" -> Jaccard 0.5, 数字不匹配 -> 不相似
    """
```

**零依赖**: Jaccard + 数字/实体用 Python 标准库 (re + set)。

---

## 5. 状态机

```
preference ──(threshold 1)──> soft rule (personal)
soft rule  ──(threshold 2)──> hard rule (company, override=True)
any state  ──(security kw)──> security   (company, override=True)
```

每次转换:
1. 写入 upgrade_chain
2. 触发 engine.add_rule（幂等）
3. 记录 audit log

## 8. 验收标准

- AC-1: detect_repeat_correction() 独立可用，字段完整
- AC-2: classify_and_remember 自动集成，correction 时返回 upgrade_action
- AC-3: 3 次同类纠正后 RuleEngine 含 company override rule
- AC-4: 安全关键词立即升格，无需阈值
- AC-5: 语义去重正确
- AC-6: 零依赖（不引入 sklearn/numpy/spaCy）
- AC-7: 阈值参数化（环境变量覆盖）
- AC-8: Feature flag 紧急回滚
- AC-9: schema 迁移 v100→v101 不破坏数据
- AC-10: 全量回归 ≥4666 测试 0 失败

## 9. 风险与回滚

### 9.1 风险

| 风险 | 缓解 |
|------|------|
| 升级过激 | 阈值默认 3 次 |
| 语义去重过宽 | Jaccard 0.7 + 数字/实体匹配 |
| schema 迁移失败 | 双写兼容 |
| rule 数量爆炸 | 幂等检查 |

### 9.2 回滚路径

```bash
# 软回滚
export CORRECTION_UPGRADE_ENABLED=0
# 重启即可

# 版本回滚
git checkout v0.9.9

# 数据库回滚
python -m carrymem.cli migrate --target v100
```

## 11. 决策记录

- DR-V10-001: 阈值选 2/3 而非 1/2 — 避免单次误纠正升格
- DR-V10-002: 语义去重用 Jaccard 而非向量检索 — 零依赖
- DR-V10-003: 安全关键词白名单绕过阈值
- DR-V10-004: 升级只升 scope 不改 TTL — 与"偏好永不衰减"对齐
- DR-V10-005: 阈值通过环境变量配置 — 支持灰度
